# Server reconcile：同步兼容与长任务

实际 Web UI 位于 `server/web/app.js`；`server/src/assets.rs` 通过 rust-embed 嵌入 `server/web/`，并非 `server/static/`。

## 请求与查询

`POST /api/reconcile` 保留现有请求字段和短请求 HTTP 200 / ReconcileReport 响应。以下情况改为 HTTP 202：

- 有效来源文本超过 **1200 Unicode 字符**（不是 UTF-8 字节）：有非空 `evidence` 时对去重后的来源文本计数，否则使用 `query`；不把同份 query/evidence 双算，answer/transcript 是上下文，不计数。
- 请求增加 `"async": true`（也接受 `"async_mode": true`）。短输入可显式异步；长输入不可强制同步。

返回：

```json
{"job_id":"UUID","status":"queued","status_url":"/api/reconcile/jobs/UUID"}
```

`GET /api/reconcile/jobs/{id}` 返回 `job_id`、`status` 和可选 `report` / `error`。状态为 `queued`、`running`、`completed`、`failed`；不存在或非法 UUID 返回 404。任务错误使用固定安全消息，不暴露原始输入、模型/服务错误或密钥。错误或重启后的任务可能已部分写入，**不得盲目自动重试 POST**。

任务最多同时运行 2 个，排队、执行中及未到期的暂存 checkpoint 合计最多 10 个；超出返回 429。任务由脱离 HTTP 请求的 Tokio supervisor 管理，HTTP 断开或关闭页面不会取消。没有整个任务 60 秒截止时间；底层 LLM 单次调用仍受现有客户端超时约束。UI 接受 200 或 202，202 时持续轮询；单个 GET 有 15 秒超时，暂时断网重试 GET 而不是重发写入 POST。

图谱投影沿用核心 durable queue；任务完成不等待图谱 LLM。配置实际图谱抽取器时，引擎默认启用单一后台 worker，提交记忆后立即唤醒处理，失败按队列退避重试，不再等 600 秒维护 tick。`--tick-interval 0` 不关闭图谱 worker；纯库调用方可显式设置 `graph_projection_worker(false)` 并自行 `retry_graph_projections`。未配置 LLM 图谱抽取器时保留队列，不把空抽取器的输出当作成功并删任务。

## 持久化与隐私

数据库 `data/memora.db` 的任务目录为相邻的 `data/memora.db.reconcile-jobs/`。只保存 UUID 命名的 JSON 状态/结果文件，不保存请求、query、evidence、answer 或 transcript。报告包含抽取出的事实，本身仍是敏感个人数据：不会保存 `extract_raw`、`ops_raw`，warnings 仅保留数量及脱敏提示；API 与持久化错误均不输出底层异常原文。

Unix 使用目录 0700 / 文件 0600；Windows 使用受保护 DACL，仅文件所有者与 SYSTEM 可访问（不继承宽松父目录 ACL）。先为临时文件限制权限，再写 JSON、sync、同目录原子 rename；启动检查不接受符号链接结果文件。权限设置失败则拒绝启动/提交，不降级公开保存。

重启扫描既有 JSON，把 `queued` / `running` 标为 `failed`，error 为 `interrupted`；**不会自动重跑**，避免重复写入。完成结果可在重启后查询。目录最多保留 256 个结果，满后返回 503；由运维在服务器停止或确认任务已终结后安全归档/删除 `completed` / `failed` 文件，不自动删除未知在途状态。建议与数据库一起纳入安全备份和保留周期管理，不提交版本库。

接口延续当前 server 无鉴权模式；不要暴露到不可信网络。任务 UUID 不是鉴权令牌，目录权限仅保护本机文件，并不替代 HTTP 访问控制。

## LLM 理解与抽取

保存价值、疑问/陈述、条件/引用、成员归属、标签、日期及遗忘意图都由 LLM 理解。宿主不再用问词/关键词否决 LLM 事实，不再规则兜底“请记住”或根据亲属称呼自动造名册；LLM 返回空记忆就不额外编造记忆。宿主仅验证结构、精确 source ID、连续原文证据、名册 ID 一致性、日期语法和写入授权；凭证防持久化、隐私/跨成员权限仍保留。

归属（2026.10.27.2）：正文中的她/他/它等代词必须结合最近会话解析成具体称呼，`o` 和 `c` 都用解析后的称呼（如「奶奶上午去医院体检去了」）；会话无法唯一解析时省略该事实。「家庭/公共」只用于全家共同事实，不得作为可确定具体个人的兜底。宿主不按关键词改写归属；「公共」是启动自动创建的真实名册成员，模型直接输出「公共/家庭」时宿主会照常接受，因此该约束只能由提示词约束模型判断。

第一人称（2026.10.27.4）：含「帮我/给我」等隐含「我」的事实只在宿主提供有效 `speaker_id` 时归属该成员，`c` 同步用该成员称呼（如「王总明天要去重庆出差」）；唯一例外是用户消息原文本身明确自报身份（如「我是王总，帮我订机票」）——这是正文自带的称呼，注册后可归给同段事实，而 transcript 没有每行说话人标注，跨轮自称不代表本轮说话人。Web 端不传 `speaker_id`，因此未绑定身份时第一人称事实按设计省略，不再默认主驾。要得到「王总」这类归属，由客户端绑定 `speaker_id` 或先把该成员注册为真实姓名，不由模型从会话猜测：「有请王总讲话」说明说话人不是王总，把「我」猜成最近被提到的人会把介绍人的行程误记到王总头上。

“小航下个月6号就要过生日了，请问送什么礼物好呢”在名册可唯一对应小航时，由记忆 LLM 保存生日事实，图谱 LLM 将证据投影成人物—生日事件关系与日期属性。消息时间为中国时区 2026-10-25 时，“下个月6号”由 LLM 理解为11月6日（本次日期2026-11-06），不推断出生年份、年龄或历法。图谱输入使用原文 evidence、真实说话人、宿主消息时间，而非规范化记忆内容。

图谱 prompt 实际加载 `prompts/v1/kg_extract_*.txt`，不再绕过版本化文件使用硬编码短提示。实体/别名不再经关键词二次否决，规范日期也不要求逐字出现在证据中。证据仍必须为连续原文，实体引用、所有权和隐私校验仍执行。旧 `HeuristicGraphExtractor` 仅为明确选择的兼容/离线测试实现，生产 LLM 路径不启用、不在 LLM 失败时自动回退。

当前 `/api/reconcile` 图谱是**已保存记忆的来源可追溯投影**，不独立把 LLM 放弃保存的任意整篇输入写入图谱；这样遗忘/修订仍能正确撤销来源。独立图谱抽取入口 `/api/graph/ingest` 同样使用配置的 LLM 抽取器。

## 精简 NDJSON 输出协议（2026.10.25.4）

模型每个物理行输出一个独立 JSON 对象，不再输出三个根数组或反复回传来源 ID、主体数组和空日期。例如：

```jsonl
{"o":"child1","t":"生活习惯","c":"小航的生日是11月6日","e":"小航下个月6号就要过生日了"}
{"done":true}
```

- 普通记忆默认 `k:"m"`：`o` 成员稳定 ID，`t` 标签 ID，`c` 事实内容，`e` 连续原文证据；可选 `d` 是严格 YYYY-MM-DD 日期，缺省/null 均无日期。
- 注册：`{"k":"r","n":"姓名","r":"child","e":"明确介绍原话"}`，可选 `a` 别名数组缺省为空。角色限 self/spouse/child/parent/other。
- 遗忘：`{"k":"f","o":"成员ID","c":"精确旧记忆全文","e":"本轮直接遗忘原话"}`。注册、遗忘仍只能来自 user_text，不能从附件指令取得授权。
- 宿主按实际请求绑定 source_id，并从 o 派生 subjects，不接受模型伪造这些字段。引号、反斜杠和文本中的换行必须使用 JSON 转义；不拼接破损记录、不补全模型未输出的内容。
- 最后非空行必须且只能有一个 `{"done":true}`。无可保存事实时仅输出此行；缺少/重复标记、标记后还有记录、坏行、提供商输出截断均为 partial。已通过校验的普通记忆仍保留，坏行只丢该行；不完整来源的注册/遗忘控制记录全部抑制，避免不完整上下文触发成员变更或删除。
- 完整旧版 register/memories/retractions JSON 仍兼容，旧条目逐项校验；无效条目不再拖累兄弟记忆。截断的半个旧 JSON 不挖掘条目。规范日期、确切证据、成员身份和写入权限仍校验，不是语义关键词过滤。

仅文字记忆抽取接口允许读取 finish_reason=length/max_tokens 的完整记录并明确标为截断；图谱、ops 和普通 chat 保持拒绝截断的行为。自 2026.10.27.1 起，文字记忆在暂存阶段进行有界完整重抽及语义细分恢复；恢复结果替代旧尝试，不把每次重抽立即写入数据库。仍不是 HTTP token 流式。

这次改变输出协议与响应后的逐条解析，**尚未启用 HTTP token 流式，也未改成每条生成即入库**。它减少重复输出并提升部分结果保留率，不保证消除网关排队或连接超时。

## 精简提示词（2026.10.25.5）

记忆与图谱各保留短系统指令和核心规则，合并重复解释、删除长概念铺陈与重复示例；不压缩实际证据、名册或标签数据。记忆仍使用 NDJSON 与 done 标记，图谱仍使用 entities/triples/pending/complete JSON，未改变解析协议。主体消歧、原文证据、原子事实、条件/否定、时间锚点、生日、隐私和完整性约束均保留。实际图谱请求包装移除与规则重复的段落，并继续使用版本化文件作为唯一来源。新增提示词长度上限及核心协议约束测试，防止重新膨胀。

## 核心长文本处理（2026.10.27.1）

### 原文、语义边界和指代

- `extraction_plan` / `long_extract` 保留原来源全文（包括空白），来源 ID 必须非空且唯一。按 Unicode 字符而非 UTF-8 字节计数；名册、会话、answer 以及多个短来源的合计长度不触发长文规划。
- **≤300 字：**直接让模型抽取 NDJSON（每行一个 JSON 对象，最后为 `{"done":true}`），不先调用规划模型。原有 ops 仍按候选情况执行；异常截断/坏记录保留有限恢复及未完成不写入保护。
- **301～2500 字：**将原文作为一个规划窗口，让模型先按语义拆分并标注指代上下文，再逐个语义块抽取 NDJSON。恰好 300 字归短链路，恰好 2500 字不做外层硬切。
- **>2500 字：**先按精确字数硬切，窗口最大 **2500 字**，步长 **2400 字**，相邻窗口重叠 **100 字**。窗口范围依次为 `[0,2500)`、`[2400,4900)`、`[4800,7300)`……，末窗保留实际剩余全文；2501 字会产生 2500 字和 101 字两个窗口。末窗即使不足 300 字也执行“模型拆分→抽取”，不绕过上下文规划。
- 同一来源按“第1窗规划→第1窗逐块抽取→第2窗规划→第2窗逐块抽取”顺序处理，不先把整篇文档全部规划，也不把外层硬窗直接当成孤立事实块。每窗原文定位单元最多 500 字、24 个；必要时合并碎行作为定位单元，但不改写或删掉原文字词。模型返回完整覆盖本窗的语义块、人物/时间消歧说明、引用位置及预计事实数，目标语义块约 1200 字，硬上限 2500 字。
- 每个块保留原文正文，另带有原文引用的上下文提示。摘要不是事实证据，也不是整块默认主人；不明确的指代不能猜测。跨窗口只传递有原文引用的有限上下文（最多 6 条，传递预算 1600 字），单块引用正文最多 1800 字。规划器不能引用未提供的单元，不能跨来源借用私有上下文。
- 每个硬窗**内部**的规划必须严格覆盖原文，没有遗漏/重复且引用合法；不同硬窗之间的100字重叠是有意保留。计划格式/完整性失败时保留本窗为未完成，不用未经模型规划的硬片段伪装成功；失败会阻断后继窗口上下文链，继续时按顺序恢复。语义选择由模型做，宿主检查结构、预算、窗口归属和原文位置。
- 重叠区相同记录按原始来源去重，不因窗口编号不同重复执行写入；不同日期和独立来源仍区分。同义但不同措辞的输出不会用关键词强行合并，不能保证模型产生的所有语义重复都自动消除。
- 抽取记录的 `e` 仍必须是当前块正文的连续原文，不接受摘要、引用上下文或会话单独充当证据。图谱输入仍是记忆的原文 `evidence`，不会拿改写文本或上下文摘要冒充事实。图谱自身的分块和证据/权限策略未改。

### 预算与自动恢复

- 普通抽取预算为 `clamp(2400 + 3 × 字符数, 4096, 8192)`。模型估计的事实数帮助规划分块；实际输出预算仍受上述公式约束。规划输出使用独立的有界预算。
- 输出截断、无完成标记或存在坏行时，先暂存合法记录，以最多 12288 tokens 从头完整重抽一次；仍不完整则请求模型把原块按语义边界细分，携带已验证上下文。输入 context overflow 可直接进入语义细分；不能安全细分则明确未完成，不无限重试、不让模型“从第 N 条接着编”。
- 每个原始来源共享 600 秒总期限、最多 96 次模型接口调用；每个初始规划块共享最多 7 次调用和 3 层细分。期限含排队和 provider 重试/退避；接口调用数不等于 HTTP 尝试数。网络超时停止该来源本轮调用；用户显式继续才开启新的一轮预算。
- 2 个来源滚动并发，共享 `QianfanChat` 限制器最多 2 路。来源正文总计最多 120000 字、最多 128 个非空来源；query/answer/transcript 各受 120000 字限制。server 另对请求及上下文、来源元数据的合计计数设 120000 字内存保护。单次完整 prompt 上限 24000 字。
- 重抽成功会替换旧结果，不累加旧尝试。细分未完全成功时按原文范围保留有效记录；跨子块证据不能合法归入一个未完成子块时，会把该子树折回原父范围，因此下一次可能重抽这个较大未完成范围，而非保证每个曾经成功的内部子块都永不重跑。

### 先暂存、再执行与继续

- `prepare_reconcile` 返回 `ReconcileOutcome::Complete(report)` 或 `Pending { report, checkpoint }`。**任一块未完成时，整个请求不执行记忆写入/修订/遗忘、成员注册或图谱入队**。有效记录保留在私有 checkpoint；标签读取可能仍初始化默认标签，这不是记忆提交。
- `report.staged=true` 表示仅暂存，`written_ids`、`revised_ids` 为空，`forgotten=0`。`memories_extracted` / `extraction.valid_records` 是按来源消除相同重叠记录后的有效解析数量，不等于唯一语义事实数或已保存数量。全协议完成也不是语义事实绝不遗漏的数学保证。
- 报告另给出 `planning_calls`、`extraction_calls`、`recovered_chunks`、`truncated_attempts`、`invalid_attempt_records` 和 `remaining_ranges`。范围是原来源 0 起始 Unicode 字符 `[start,end)`，不是 UTF-8 字节；不同硬窗的待处理范围可能重叠，不能取并集后就宣称全部完成。核心会在提交前重新校验每个硬窗的原文覆盖；缺窗、错误窗口编号、错误重叠范围或来源字段不一致均保持暂存，原因标为 `coverage_invalid`。错误原因使用固定安全代码，不透传 provider 原始异常。
- server 仅在内存保留完整请求和 checkpoint，最长暂存 30 分钟；主动定时到期清理，继续消费时取消旧定时器，并有访问时清理兜底。**重启丢失暂存，默认不把完整原文写到磁盘，也没有公开读取 checkpoint 的接口。** 已保存记忆仍保留自身证据摘录；上下文持久化只保留原来源/单元/字符位置，不保存整段引用或模型摘要，以免把其他人的原文附到当前记忆权限下。
- 暂存报告通过 `resume_id` / `resume_expires_in_secs` 给出继续入口：`POST /api/reconcile/resume/{resume_id}` 返回新的 202 任务。令牌原子消费，下一代使用新 UUID；已消费、过期或重启丢失返回 410。继续复用已完成范围，重跑未完成范围。UI 提供“继续未完成块”，不会重发整篇请求；原输入保留到最终完成。
- checkpoint 及继续令牌不写入任务文件。轮询时从内存为仍有效的任务报告附加令牌；重启后历史暂存报告明确不可继续。UUID 不构成鉴权，当前 server 仍不可暴露到不可信网络。
- 兼容库入口 `reconcile_turn` 仍返回 `ReconcileReport`，但会丢弃 Pending 的 checkpoint；需要继续能力的宿主必须使用新的 prepare/resume API。显式 `source.truncated=true` 的原输入无法靠续跑补全，必须提供完整来源。
- 抽取恢复不会重复执行副作用；**最终 apply 仍是原有逐条数据库操作，不是整个请求的单事务，也没有跨进程 exactly-once 账本**。apply 失败或 POST 响应丢失时，后台可能已经部分提交，不能据此自动重放。checkpoint 一旦交给 apply，不因失败重新放回。
- 去重区分事件日期与独立来源；不再以同正文把不同日期事件合并。不同来源不静默共享 graph acknowledgement；已有候选的日期及已知来源也需匹配，无法唯一对应的 ops 回退到验证后的事实路径。

### 图谱与候选检索

- 图谱投影仍随记忆事务入队，后台执行，前景不等待图谱 LLM；修订/遗忘的版本栅栏、来源和隐私策略不变。本轮没有独立将全文写入图谱或迁移历史数据。
