家庭知识图谱需求说明（金融 / 医疗 / 教育）
1. 目标
为「家庭场景」构建一个可长期积累、可查询、可更新的知识图谱，覆盖三个领域：金融、医疗、教育。

图谱以家庭成员为中心，把对话与日常信息沉淀为：

实体（人、机构、账户、疾病、学校、课程等）
关系（谁过敏什么、谁拥有哪张卡、孩子在哪上学等）
属性与时间（剂量、保额、年级、生效/失效时间等）
最终能力应支持：

从家庭日常表述中持续补充、纠正图谱；
按成员、领域查询「相关知识」；
区分普通信息与隐私信息；
同一事实在不同条件/时间下可以并存，而不是互相粗暴覆盖。
2. 范围与原则
2.1 必须遵守
以人为中心：尽量把信息挂到具体家庭成员；避免无人归属的悬空知识。
原子化：一条关系只表达一个可独立更新的事实。
可演化：支持新增、纠正、过期、暂停；保留必要历史，不轻易物理删除。
条件与例外单独保留：例如「平时喜欢辣」与「胃不舒服时不吃辣」必须同时存在。
否定要显式表达：例如「不再上钢琴课」「不对花生过敏了」。
隐私可标记：医疗细节、资产、成绩等可标记为隐私；仅本人（或授权场景）可见。
跨领域可连接：例如培训班学费同时涉及教育与金融；儿童医保报销同时涉及医疗与金融。
2.2 不做（初期）
不做开放域百科式全量本体；
不追求一次定义成百上千种关系；
不把「聊天原文」直接当图谱唯一结构（原文可作为证据，但图谱要结构化）。
3. 家庭场景清单（必须覆盖）
3.1 医疗
过敏与饮食禁忌（如：孩子对花生过敏；家里不吃香菜）
慢病与病史（如：老人有高血压；某人去年做过手术）
用药与疗程（如：每天吃某种药、剂量与频次）
就诊与体检安排（如：下周去某医院复查）
疫苗与生长发育记录（身高、体重、接种）
陪护与紧急联系（谁陪诊、过敏发作时联系谁）
与保险相关的就医报销信息（可与金融域交叉）
3.2 金融
账户与归属（工资卡、房贷账户分别属于谁、在哪家机构）
家庭支出分工（水电谁付、培训费谁付）
贷款与定期扣款（房贷/车贷还款日与金额）
保险保单（投保人、被保险人、受益人、保额、续费）
投资与风险偏好（如：不做某类高风险产品；有定投习惯）
预算与限额（餐饮月预算、旅游年预算）
重要缴费/还款日期
3.3 教育
在读信息（学校、年级、班级）
兴趣班/课程（科目、时间、地点、机构、老师）
成绩与阶段评价
学习目标（升学、考级、竞赛）
作业与作息约束（几点前完成作业等）
家校沟通事项（家长会、班主任联系方式）
因健康等原因暂停课程（与医疗交叉）
4. Schema 要求（概念层，不限定存储形式）
4.1 实体类型（MVP 必须支持）
通用

家庭成员（Person）
组织机构（医院、银行、学校、培训机构、保险公司等）
地点（校区、院区、网点等，可选用）
事件（就诊、家长会、还款日、体检等）
材料/单据（报告、保单、成绩单等，可挂证据说明）
医疗

疾病/症状状况（Condition）
过敏原/物质（Allergen/Substance）
药品（Medication）
疫苗、手术/处置（Vaccine/Procedure，可合并为处置类）
测量指标（血压、血糖、身高体重等）
金融

账户（Account）
负债（房贷、车贷等 Liability）
保单（Policy）
投资标的（可粗粒度 Instrument）
预算项/应付款（Budget/Obligation）
教育

学校（School）
课程/项目（Course/Program）
老师（Teacher）
班级（Class，可选用）
测评/成绩（Assessment）
教育目标（EducationGoal）
每个实体至少包含：

稳定标识与规范名
别名（如「儿童医院」「市儿童医院」）
状态（有效/已结束/暂停/未知）
所属领域（医疗/金融/教育，可多领域）
隐私标记
首次出现与最近确认时间
可扩展属性（如剂量、保额、年级）
4.2 关系类型（MVP 必须支持，名称可调整但语义必须有）
医疗

过敏（Person → Allergen）
患有/存在状况（Person → Condition）
服用（Person → Medication）
就诊于（Person/Event → Organization）
照护（Person → Person）
禁忌/冲突（可选）
金融

拥有（Person → Account/Asset）
欠款（Person → Liability）
支付（Person → 费用类/其他成员/机构）
投保/承保（Person ↔ Policy ↔ Organization）
受益（Policy → Person）
预算用于（Family/Person → 类别或项目）
教育

就读于（Person → School）
参加课程（Person → Course）
由谁授课（Person/Course → Teacher）
取得成绩（Person → Assessment）
目标是（Person → EducationGoal）
跨域示例（必须允许）

因病暂停课程（Course 边暂停原因指向 Condition）
课程费用由谁支付（Course ← pays_for ← Person/Account）
就诊费用由某保单覆盖（Visit/Event ← covered_by ← Policy）
每条关系至少包含：

主体、关系类型、客体
生效/失效时间（或“截至某日仍有效”）
条件限定（如仅工作日、仅胃不舒服时）
极性（肯定/否定）
置信度或来源可靠度（可粗可细）
证据说明（对应哪次表述/哪份材料）
隐私标记
4.3 丰富度要求（验收导向）
图谱应能表达下列「并存」情况，而不是互相覆盖：

「喜欢吃辣」与「胃不舒服时不吃辣」
「周二上钢琴课」与「因膝盖不适暂停钢琴课」
「有房贷」与「房贷已还清」（历史可查，当前状态正确）
「对花生过敏」与后来「经医生评估已不过敏」（需时间线，不可只留一句）
同一对成员/对象之间允许存在多条不同条件或不同时期的关系。

5. 输入与输出期望
5.1 输入（示例）
家庭自然语言，例如：

「小航花生过敏，误食要立刻送医，先打电话给妈妈。」
「房贷每月 8 号从我招行卡扣 9200。」
「小航在实验小学三年级，周二晚上去少年宫钢琴课，学费我出。」
「姥姥有高血压，每天吃氨氯地平，早上一次。」
也可以来自家庭材料中的关键信息（体检小结、课表、缴费提醒等），但初期以对话为主。

5.2 输出（概念结果，不限格式）
对每次有效输入，应能得到：

涉及哪些实体（新建或复用）；
新增/更新哪些关系；
哪些信息是隐私；
哪些是条件句、否定句、过期句；
可用的简短证据摘要。
查询时应能回答例如：

「家里谁对什么过敏？」
「这个月有哪些固定扣款？」
「小航这学期有哪些课？有没有暂停的？」
「谁有慢性病，日常药是什么？」
6. 隐私与共享规则
默认：家庭成员之间的非隐私知识可共享查询。
隐私知识（尤其医疗细节、大额资产、敏感成绩等）：仅对本人（关系主体成员）可见，除非另有明确授权规则。
「本人」以该条知识所归属的家庭成员为准。
7. 质量标准
可追溯：重要关系能对应到证据表述。
可更新：纠正信息时更新当前状态，并合理保留历史。
少幻觉：不确定就标未知，不编造机构全称、金额、诊断。
规范化：同义称呼尽量合并到同一实体（别名机制）。
克制：优先使用受控的实体类型与关系类型，不随意发明同义关系名。
家庭可用性：结果应能直接服务家庭问答与提醒，而不是仅适合专业分析师。
8. 分期建议（仍属需求，不是技术方案）
第一期（必须）
落地上文 MVP 实体与关系；支持三域基础问答与跨域连接中的「学费支付」「因病停课」。

第二期
补齐测量指标时序、预算、受益人、家校联系人、材料类证据。

第三期
更细的投资标的、手术史、竞赛轨迹等，按真实使用频率扩展。
